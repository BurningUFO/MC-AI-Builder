# M6-A NPC 第一人称 RGB

## 使用

1. 用原有启动器进入隔离练习世界或已授权的 BMC4 副本。由施工系统生成 NPC 后，站在已批准区域内，并保持 NPC 位于客户端加载范围内。
2. 在游戏中输入 `/architect observe`。游戏会短暂切换到 NPC 第一人称相机，随后恢复原来的玩家相机及视角模式。观察 ID 会显示在私聊消息中。
3. 在项目的 `.cache/observations/<实例目录名>` 打开相同 ID 的 PNG 和 JSON。Python 可通过现有 `ArchitectClient.observation()` 查询最近一次状态，再用 `observation_image()` 校验尺寸、路径及 SHA-256。

## 采集方式

Forge 47.4.20 在 `AFTER_LEVEL` 事件读取渲染中的相机、投影矩阵及 Minecraft 主渲染目标。至少经过两帧世界渲染，且相机实体、位置和眼高与客户端收到的 NPC 状态一致、渲染朝向与服务端姿态相差不超过 2° 时，渲染线程才读取像素。手持物和 HUD 在之后绘制。图片编码及本地写盘异步完成，输出 RGB PNG 并保持实际画面比例，最大 768 × 432。每个实例保留最近 24 次成功观测，隔离测试模式另外保留最近两张未缩放的图。

观察仅由本机单人世界的已授权玩家发起。服务端确认目标为当前施工 NPC，且所在维度、授权区及区块满足条件。客户端失去目标、切换连接或等待超过 5 秒时停止观测。采集使用当前主渲染目标，目标或姿态未就绪时可以等 NPC 停稳后重试。本阶段模型调用为 0。

## 游戏内验收

Minecraft Java 1.20.1、Forge 47.4.20 的最小实例和 387 模组的 BMC4 隔离实例均通过。BMC4 使用含 Oculus 的默认渲染配置。验收场景为两个新建的隔离练习世界。

测试玩家用原版物品交互搭建 42 块蓝色染色玻璃和橡木参考墙，既有施工执行器通过真实放置创建 NPC。隔离夹具设置 NPC 的观测站位和朝向。玩家站位与 NPC 相距 11 格，且初始视角为第三人称。两次实拍均通过服务端位置与姿态校验，图片 SHA-256 不同，中心区域实测分别为蓝色调和橡木暖色调。观察前后，玩家和 NPC 坐标、已批准区域及其边缘的方块摘要、NPC 库存均一致。

| 环境 | 输出尺寸 | 垂直 FOV | 请求至读帧 | 像素读取 | 采集时 FPS |
| --- | --- | --- | --- | --- | --- |
| 最小 Forge | 731 × 432 | 70° | 156–168 ms | 4.4–5.7 ms | 37–40 |
| BMC4 | 731 × 432 | 70° | 174–176 ms | 4.6–6.0 ms | 23–40 |

两次成功采集后均确认原玩家相机及第三人称模式恢复。最小 Forge 还在切换后的下一帧注入实际客户端实体丢失，验证错误为 `npc_not_visible`，玩家相机恢复，且图片数量保持一致。已经不可见的 NPC 再次观察时失败。从另一维度发起请求被拒绝。用原版流程退出并重开后，原 NPC 可生成带新 ID 的图像。Forge 和 BMC4 的最终测试客户端均正常保存退出。

首次 BMC4 测试发现客户端仍在插值朝向，当时的渲染角度与测试要求偏离约 44°。采集加入服务端姿态对齐和眼高收敛检查后，两张验证图均对应目标方向。启用额外光影预设的配置留待后续验证。

## 复现与证据

构建 Bridge 后，在项目根目录执行：

~~~powershell
& .\tools\m1.ps1 Build -Offline
.\.venv\Scripts\python.exe -B -m tests.m6_a_smoke forge
.\.venv\Scripts\python.exe -B -m tests.m6_a_smoke bmc4
~~~

BMC4 测试沿用现有隔离模组包。最终部署 JAR 与 Forge 构建产物的 SHA-256 一致，30 项 Python 单测通过。公开证据来自专门搭建的测试场景。
