# M4 生存施工验收

Minecraft Java 1.20.1、Forge 47.4.20、Fake Players 3.0.0。测试在独立生存世界及 BMC4 隔离实例中运行。 [启动与复现步骤](m4-guide.md)

## 最小 Forge 生存世界

| 项目 | 实际结果 |
| --- | --- |
| A 取料和建造 | 测试玩家经原版箱子菜单投入已知物资。NPC 从批准的单箱分两趟取得 30 个建筑物品，记录箱子扣减与背包增加。30 次原生放置，各消耗一个物品，逐格回读 30/30，箱内无关的 4 个黑曜石保留。 |
| B 缺料与补给 | 透明玻璃不足时完成已可建的部分，并在聊天报告还缺 4 块。玩家向同一箱补入 4 块并确认继续后，NPC 完成施工。 |
| E 库存和审批 | NPC 走向仓库时，玩家改变箱内物品，任务暂停且保持零搬运。审批前改变箱子快照使旧审阅失效。越界箱子和无玩家审批的 HTTP 写入被拒绝。已用编号重放未产生新的库存扣减。 |
| E 工具与拆后重开 | 仅剩 1 耐久的铁镐真实损坏，随后报告缺 3 次镐耐久。玩家补一把镐后继续，拆开 4 格时正常保存退出。重开后世界、箱子、工具和原 NPC 一致，只在剩余步骤取出并放置 4 块蓝色玻璃。 |
| E 搬运中重开 | 第一趟取完后在去施工点途中保存退出。重开核对同一 NPC、真实供料箱、背包和回执，继续完成剩余工作。共三次正常保存退出，两个中断点均通过一致性检查。 |

Forge `useItemOn` 产生真实右键和容器开启事件。搬运使用 Forge `InvWrapper.extractItem` 和 NPC 的 `SimpleContainer.addItem`，属于游戏主线程的容器转移。施工的放置、拆除与工具损耗由原有游戏机制产生。 [完整收支与终态](m4-evidence/survival.json)

首次拆后重开遇到空槽残留标签导致箱子指纹误报。已按实际存档语义规范化空槽，并用含物品数据与耐久的背包内容核对 Fake Players 的槽位重排。完整游戏复测通过。

## BMC4 的白名单与真实改图

在 387 个启用模组的隔离副本中，运行时注册表核对了下列方块及其实际放置物品。两种 Quark 方块的注册 ID 与物品 ID 在本版本相同，放置验证仍依据注册表的 `BlockItem` 映射。

| 实测方块 ID | 实测物品 ID | 实测状态与动作 |
| --- | --- | --- |
| `chipped:stacked_spruce_planks` | `chipped:stacked_spruce_planks` | 默认状态，4 块。取料、逐块放置、拆除及恢复通过。 |
| `quark:red_shingles` | `quark:red_shingles` | 默认状态，6 块。取料、逐块放置、拆除及恢复通过。 |
| `quark:red_shingles_stairs` | `quark:red_shingles_stairs` | 东、西两种朝向，`half=bottom`、`shape=straight`、`waterlogged=false`。取料、逐块放置、拆除及恢复通过。 |

C 用确定性后端先施工 30 块，再用实际方块和工具替换 12 块模组方块，最后恢复原来的 12 个完整状态。拆除事件记录了 2 块红瓦楼梯、6 块红瓦和 4 块 Chipped 木板掉落。Chipped 的额外掉落由实际交互产生，预览中的原始掉落表估算未计入。拆下的物品留在世界中，这轮施工从批准箱存取得恢复用料。首轮高位楼梯缺少可达支撑，调整为先放同层实心瓦后通过。

D 使用已登录 ChatGPT 的官方 Codex SDK 0.171.0，显式指定 `gpt-6.2-sol`、`medium`，保留只读沙箱和拒绝工具审批。三个真实模型回合分别输出新建、局部屋顶改图和库存查询，M2 按实际世界和仓库计算动作及缺口。8×3 窗墙施工到 26/30 块时暂停。人工批准只改屋顶的 V2 后，NPC 保留 22 块、拆下 4 块旧屋顶，因缺 6 块红瓦和 2 块楼梯停工。玩家补入同一箱并确认继续后，NPC 取出并放置 8 块，30/30 个坐标、ID、状态吻合，批准区域外零差异。改图后剩余的石砖台阶保留在原 NPC 背包，旧确认与重复确认都未重复扣料。

模型验收累计 3 回合、35,619 Token，低于 10 回合、150,000 Token 的共享账本上限。Blender 重开确认审阅前现场 26 块、拟建 30 块、同一审阅哈希和两角度相机。 [逐轮模型证据](m4-evidence/codex-turns.json) · [正侧预览](m4-evidence/proposed.png) · [后侧预览](m4-evidence/proposed-rear.png)

E 在 BMC4 完工后正常保存退出。重开时通过 BCLib Guardian 保留备份，然后核对了三种模组方块、箱内余额、4 块剩余石砖台阶、工具耐久和同一 Fake Player。搬运与施工回执均未重放，随后第二次正常保存退出。所有写入来自 D 盘隔离实例。 [白名单、逐块记录和重开证据](m4-evidence/bmc4.json)
