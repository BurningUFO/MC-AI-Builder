# M6-D 视觉反馈与施工闭环

## 操作

使用 [M6 游戏内体验指南](m6-guide.md) 启用隔离副本的视觉监管。首次模型分析沿用 M6-C 的主动环境观察。施工半程、执行异常和完工时 Forge 安排有限的现场复查。玩家也可以直接请求检查或在施工时描述改图。

系统记录 `OBSERVE → INTERPRET → PLAN → REVIEW → ACT → VERIFY`。Forge 关联 NPC、区块、方块样本和当前施工版本。模型提出继续、补拍、报告或具体改图。执行调用仍由施工事务及签名玩家确认驱动。完工聊天中的精确一致性结论来自 Forge 的最新逐格核验。

## BMC4 实际施工

使用 387 个整合包 JAR 的 D 盘合成自然地形副本。两版分别通过游戏内玩家审批 `2665be8d3a617cbc` 和 `41f6b3be8513fa09`，并生成 Blender 工程和两个视角的审阅图。

| 游戏检查点 | 实测结果 |
| --- | --- |
| 设计 | Codex 根据真实 NPC 图像和局部地基读数生成 20 块窗墙。审批前的方块快照与基线一致。 |
| V1 取料与半程 | 同一个 NPC 从批准的箱子取用 16 件真实材料，放置 10 块，然后在自动半程检查点停止。 |
| 视觉反馈 | 近处木板遮挡窗格时，模型报告证据不足，V1 保持暂停。Forge 找到安全观察视角后，本地检查确认新画面对准真实透明窗格，最后一轮 Codex 根据草坡背景和窗框提出只换玻璃的 V2。 |
| V2 审阅 | 8 块保留，2 块替换，10 块补建，零冲突。Forge 统一使用审阅与执行的邻块安全检查。区域内短草的同高度侧邻可施工，其下方支撑和施工范围仍受保护。 |
| V2 施工 | 玩家批准同一审阅后，原 NPC 从原箱子取得蓝色玻璃、石砖台阶和铁镐。2 次拆除及 12 次放置均有可追溯的 Forge 交互证据，已保留方块没有出现在动作清单中。 |
| 完工 | Forge 的新鲜世界回读核对 20/20 块的完整 BlockState，非目标变更和区域外变更均为 0。真正的 NPC 完工帧使用本地像素校验及配对方块状态复查。 |
| 保存与区块 | 反复正常保存并重开后，Forge 核对原 NPC、现有世界方块、背包、供料箱和未完成事务。测试玩家进入下界使施工区真实卸载后，尝试批准被拒绝。回到区域后，原 V2 审阅摘要仍匹配。 |

共享预算记录为 10 轮和 131,236 Tokens。其中 M6-D 用了 6 轮和 78,224 Tokens。真实模型为 ChatGPT 登录的 `gpt-6.2-sol`，思考深度为 `medium`，实际耗时 7.27–15.92 秒。最后一轮仅生成具体改图。终态与故障验收使用本地确定性复查，避免超出授权的模型预算。施工前、V2 审阅前和完工三张有效样本的拍摄时间为 115–288 毫秒，像素读回为 2.7–37.2 毫秒，采样时客户端读数为 2–40 FPS，配对采样相隔 4–6 Tick。

## 正常场景与故障回归

- 第二处自然地形完成 20 块 V1 窗墙 `12a1c1f61a2eaa90`。本地确定性后端基于真实配对画面复查，施工区遇到无法安全调整的站姿时使用现位置采样。玩家确认继续后，最终世界保留 V1，共生成一份候选。
- 在暂停的半程现场模拟模型超时，并等待另一张真实采样超过 60 秒。两次都核对施工步数、方块和候选状态。画面被拒绝后由玩家确认继续原任务。
- 游戏客户端丢失 NPC 实体追踪时，停止视觉复查，恢复玩家相机，模型调用次数与世界快照保持一致。过期的 V1 审批在 V2 生效后也被拒绝。
- Forge 离线构建及 46 项 Python 测试通过。原合成源存档及其模组文件清单的 SHA-256 仍与复制前一致，D 盘验收副本从游戏内正常保存退出。
