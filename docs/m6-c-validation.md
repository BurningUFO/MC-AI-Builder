# M6-C 主动观察与场地适配

## 使用

在受管理的 BMC4 世界副本里批准施工区、NPC 站位、建筑标记和供料箱。运行 Codex Architect Runtime 时，只有愿意发送 NPC 截图才启用 `--share-observations`。该开关使用现有启动器的持久化预算账本，也可通过 `--codex-budget-log` 指定已分配的测试账本。

在游戏内输入 `/architect survey 先查看这里的地形，再设计一面六至八格宽的窗墙。保持地形不动。` 模型可以提出站点移动或转头。安全到达后，Forge 使用同一个 Fake Player 的第一人称画面和配对局部方块采样重新审视。设计理由、材料、冲突和 Blender 预览通过现有候选审阅回到游戏。只有点击对应版本的批准按钮才开始施工。

## 范围与限制

- 每条签名需求最多捕获三次。一次观察步行距离最多八格，最长 110 个游戏刻。转头目标也必须在已批准、已加载的近距离范围内。
- 观察从批准的 NPC 站位开始。Forge 检查每个寻路节点的站位、前后高差、液体、碰撞、危险表面和区块，不强制加载区块。移动、切换申请和失去授权都有独立的终止条件。
- Forge 只从已批准区域内给出候选地基。原点相对玩家标记最多水平四格、垂直两格。审阅逐一回读候选方块及支撑，审批哈希绑定最终位置、旋转和 BlockState。未启用主动观察的普通设计沿用 M5-B 的原点和朝向规则。
- 仅支持既有参数化窗墙和已验证材料。水面、没有稳定支撑、被已有方块占用或暂时失载的地形，需要重新选址或另行处理。图像和局部文字采样只支持受控的单机隔离实例。
- 图像沿用 M6-B 的 HUD 前采集和元数据剥离。SDK 只收到这条建筑请求、相对地形、方块状态、简化任务状态、已检查局部选择和图像。每次模型调用继续使用只读、禁用执行工具和独立玩家审批。

## 2026-11-22 游戏内验收

在 D 盘 BMC4 合成自然地形副本进行，沿用 387 个整合包 JAR 与项目的两个施工模组。测试玩家从游戏聊天提交相同的巡查与设计需求。两个场地各使用两张真实的 NPC 第一人称 PNG。模型选择了安全站位，Forge 完成实际步行后重新采帧。模型随后选择对应地基、朝向和收顶形式。

| 实际场地 | 连通站位高差 | NPC 走动与偏航 | 生成与审阅 |
| --- | ---: | --- | --- |
| 较平缓的草地带 | 2 格 | 3 格，135° → 156.09° | 5×4 窗墙，90° 朝向，底半石砖台阶收顶，审阅 `5cef5ae37cb92ceb` |
| 阶梯状坡地 | 3 格 | 3 格，225° → 202.5° | 5×4 窗墙，270° 朝向，深色橡木收顶，审阅 `63800ffc51abf44b` |

两份候选均生成可打开的 Blender 工程和两个角度的渲染。Forge 回读显示各有 20 项补建、零冲突。测试玩家拒绝候选前，施工任务仍为空，包含一格监测边的每个方块与巡查前快照一致。已实际拒绝越距、无支撑、错误重复和过期观察操作。独立进程正常保存退出，源副本模板的世界与模组文件清单及 SHA-256 保持一致。

使用 ChatGPT 登录的 `gpt-6.2-sol` 和 `medium`。四轮按顺序耗时 15.54、13.80、8.99、14.58 秒，分别消耗 12,982、13,268、13,229、13,533 Tokens，共 53,012。Forge 离线构建和 42 项 Python 单测通过。四张图的采集耗时为 131–496 毫秒，像素读回为 1.7–45.2 毫秒。首次取样时客户端读数为 2 FPS，之后三张为 31–40 FPS。
