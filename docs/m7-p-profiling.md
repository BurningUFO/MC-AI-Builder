# M7-P 性能测量与故障定位

在 Windows PowerShell 设置 `$env:MC_AI_BUILDER_PROFILE = '1'`，再从同一个窗口启动游戏与 Runtime。Forge 的 `/progress` 会附上当前任务的 `performance` 摘要。授权副本中的 Runtime 会在预览目录写入 `performance.jsonl`。记录包含本地序列和关联 ID，以及耗时、结果和分类。预览素材、对话正文、图片、凭据和完整世界数据由原有接口单独管理。

## 度量口径

- 施工实际耗时从已批准任务准备好执行起算，到终态和检查点写入完成。审批等待、Runtime 排队、模型、观察、场地样本、造型与渲染另行记录。A 与 B 使用同一份确定性住宅需求，便于对照执行器。模型回合的开销从实际模型验收单独统计。
- Java 用单调时钟统计耗时，用世界 game tick 记录执行进度。世界 Tick 数除以实际经过秒数得到观察 TPS。客户端 FPS 每 20 tick 采样。每 Tick 的位置增量累计为 NPC 步行和跳跃距离。
- 各施工状态的经过时间合成一条时间线，区分调度等待、寻路中、取料往返、挖掘及人工或异常暂停。CPU 计时按操作单独累计。有些操作在同一 Tick 或另一计时区间内执行，统计项之间存在包含关系。
- 服务器 Tick 取 Forge 的 START 到本模组 END 采样点。动作包含抽样时的调度间隔。高分位为固定直方图区间上界。完整玩法记录可用逐动作时间戳重新计算分位数。
- Forge 在服务端内存累计计时。Runtime 使用有界队列在后台写出诊断。任务、请求、观测和策略 ID 可关联记录。重开会生成独立的单调时钟段，存档保留决定恢复所需的进度、动作及审批信息。

## 对照基线与优化顺序

原执行器的 183 块完整运行耗时 165.28 秒，施工需求到终态回读为 171.38 秒，吞吐量 66.43 块／分钟。NPC 移动 319.92 格。观察 TPS 为 20.00，客户端 FPS 均值为 39.96。

| 施工阶段 | A 组实际经过时间 |
| --- | ---: |
| 施工寻路移动 | 55.99 s |
| 动作之间的调度等待 | 55.30 s |
| 仓库往返移动 | 44.22 s |
| 放置站位跳跃及其他工作 | 9.77 s |

M7-A 的 13 次往返跨两个版本，包含改图后的补料。本轮 A 直接从空地施工最终版本，同场对照以它实测的 12 次往返为基线。

NPC 共做了 155 次路径搜索，累计计算 350.78 ms。1976 次候选站位检查累计 40.28 ms。逐块放置的实际交互累计 278.86 ms。12 次取料交互累计 319.02 ms。391 次持久化检查点写入累计 5.80 s。这些 CPU 统计与经过时间存在重叠。

因此优先缩短相邻合法动作间的调度等待，在相同支撑层内提高空间连续性，并把紧邻阶段的材料装进同一趟。住宅中成功放置与下一目标的距离平方不超过 2 时，且下一动作是空位放置，间隔可从 6 Tick 缩短为 2 Tick。供料单趟最多 48 件，仍按剩余队列、真实槽位和箱内数量计算。每次实际交互照常核对视线、距离、目标和库存。原导航超时与写前检查点继续生效。连续工序跨越路线较长的区域时，NPC 仍逐段导航。

A 组一次更早的运行在完成 113 块后遇到原生放置拒绝。Forge 收到右键事件，目标仍为空气，物品数量未变。原因没有从这次证据中确证。新版在实际放置前还会检查实体占位，短时等待后只作有限重试。

B 组采用优化调度后，调度等待为 25.43 秒，仓库往返为 13.58 秒，寻路计算由 155 次降到 118 次。NPC 到达供料箱后才计算完整的装箱组合，计划计算由 438 次降为 4 次。普通工地移动仍耗时 51.16 秒，是 B 组耗时最高的部分。该结果来自一栋住宅与一次完整的 A/B 配对运行。

## 故障归因

| 分类 | 典型信号 | 恢复操作 |
| --- | --- | --- |
| 模型与额度 | 认证失败、超时、结构化输出无效、额度耗尽 | 在启动器核对登录与额度。必要时重发建筑需求 |
| Bridge | 本地心跳丢失、连接无法建立 | 回到已加载的副本，退出暂停菜单，检查游戏和 Runtime 日志 |
| 请求与版本 | 请求、确认或并行策略过期 | 根据当前建筑版本发出需求，使用当前的审阅和确认 |
| 建筑与渲染 | Schema、尺寸与方块约束、Blender 渲染错误 | 调整参数或检查本地 Blender 和资源，再重新审阅 |
| 视觉 | 相机切换、帧配对失败、现场样本过期 | 恢复游戏视角后重新观察。并行规划可继续使用 Forge 摘要 |
| 导航与交互 | 找不到有效站位、导航超时或保护拦截 | 核对通道、支撑、交互面、现有方块和授权边界 |
| 仓库与工具 | 缺料、工具不足、箱内数量变化 | 用游戏命令核对箱子与数量，再由玩家确认继续 |
| 审批与地形保护 | 无权审批、现场变化、敏感相邻块 | 由授权玩家重新审阅实际世界和候选 |
| 游戏与恢复 | 整合包异常退出、区块卸载、检查点不一致 | 正常重开副本并加载施工区，再核对原 NPC、背包和供料箱 |

A 组第一次开工检查发现占地内有 8 株 `minecraft:grass`。测试员通过游戏交互清理住宅占地。三组从同一份正常保存的合成地形及箱内库存复制，各自签署施工区、供料箱和住宅审批。每组在计时前由测试脚本移除范围内少量游荡的原版动物，并逐格核对共同的起始场地。
